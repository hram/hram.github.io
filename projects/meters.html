Автоматизация

meters

Агрегатор «семейства счётчиков»: вода, газ, электричество — один экран, одна кнопка.

Что это

FastAPI-портал-агрегатор — верхний уровень системы из трёх сервисов. Сам к поставщикам не ходит: забирает данные у двух нижележащих порталов по HTTP через адаптеры и сводит их в единый дашборд.

Адреса источников задаются конфигурацией, поэтому источники подменяемы, а добавление нового поставщика не затрагивает агрегатор.

Задача, которую решает

После автоматизации двух поставщиков появились два разных интерфейса — пользовательский сценарий распался. Агрегатор возвращает его к одному экрану: все счётчики, один взгляд, одно действие.

Что демонстрирует

  • Системное мышление: два источника плюс агрегатор, взаимодействие по HTTP, ответственность разделена осознанно — архитектура на уровне системы, а не файла.
  • Размножение решения: один отработанный шаблон → три сервиса за срок, за который обычно делают один.
  • Доведение до эксплуатации: Docker Compose собирает связку целиком; сервисы работают круглосуточно.
  • Продуктовую эмпатию: документация написана для человека, который не программист.

Стек и подход

Ядро: Python 3.10+, FastAPI, Uvicorn, Jinja2, httpx, APScheduler, SQLite — стек общий с нижележащими порталами.
Ключевое отличие: слой адаптеров к источникам вместо клиента конкретного поставщика.
Deploy: Docker + Compose — единственный проект семейства, собирающий всю связку.

След ИИ-процесса

Три сервиса семейства сделаны за одни и те же четыре дня по общей структуре: сначала отрабатывается шаблон интеграционного портала, затем он повторяется на втором поставщике, затем поверх ставится агрегатор. README описывает порядок развёртывания связки — система задумана целиком, а не собрана из накопившихся кусков.

Почему это отвечает роли «превратить AI-кейсы в стандарт»

Самая наглядная иллюстрация тезиса «ИИ ускоряет не написание кода, а размножение хорошего решения». Ценность создаёт шаблон и разделение ответственности, а не скорость набора текста — именно это и стандартизируется.
