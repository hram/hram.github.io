# Инструкция: перевод статей hram.github.io на английский

Для агента, который переводит статьи. Каталог `prompts/` исключён из сборки Jekyll
(`exclude` в `_config.yml`), на сайт этот файл не попадает.

## Разделение ролей

| Что | Кто |
|---|---|
| Перевод статьи, файлы в репозитории, карточка в `en/articles/index.md` | **ты** |
| Коммит, push, деплой на GitHub Pages | мета-агент career-portal |
| Индексация: sitemap, Яндекс.Вебмастер, GSC, `noindex` у `/en/articles/` | мета-агент career-portal |
| Публикации на внешних площадках (Habr и т.п.) | не твоя задача |

**Не делай `git commit` и `git push`.** Оставь изменения в рабочем дереве
`/mnt/fastdata/hram/projects/hram.github.io` и опиши, что сделал. Не убирай
`noindex: true` и `sitemap: false` из `en/articles/index.md` — это делает мета-агент
в момент публикации.

## Как устроен сайт (что важно для перевода)

Jekyll + тема just-the-docs, сборка через GitHub Actions. Русская статья лежит так:

```
articles/<slug>/
  article.md          # русский оригинал, permalink: /articles/<slug>/
  assets/             # картинки, общие для обеих языковых версий
```

Английская версия кладётся **в ту же папку**, рядом с оригиналом:

```
articles/<slug>/
  article.md          # ru (правится минимально, см. ниже)
  article.en.md       # en, permalink: /en/articles/<slug>/
  assets/             # общие картинки; отдельные en-картинки — с суффиксом .en
```

Языковые версии связывает поле `translation_key`. По нему шаблоны сами:
- выводят `<link rel="alternate" hreflang="ru|en|x-default">` в `<head>`;
- рисуют переключатель `RU | EN` в шапке.

Ничего из этого руками в статью добавлять не нужно. Если `translation_key` не совпадает
или задан только у одной версии, пара не свяжется и hreflang не появится.

## Front matter

Русская статья — единственная правка оригинала: добавить одну строку `translation_key`
(равна имени папки `<slug>`). Текст оригинала не менять.

```yaml
---
layout: default
title: "…"
description: "…"
date: 2026-09-24
permalink: /articles/price-tag-scanner-ab/
translation_key: price-tag-scanner-ab   # <- добавить
nav_exclude: true
---
```

Английская версия `article.en.md`:

```yaml
---
layout: default
title: "…"                      # перевод, в кавычках
description: "…"                # перевод, 120–160 символов, в кавычках
date: 2026-09-24                # та же дата, что у оригинала
lang: en
locale: en_US
translation_key: price-tag-scanner-ab
permalink: /en/articles/price-tag-scanner-ab/
nav_exclude: true
---
```

Правила:
- `title` и `description` **всегда в двойных кавычках** — двоеточие в заголовке без
  кавычек ломает YAML и сборку (уже был такой инцидент со статьёй gdebenz).
- `lang: en` и `locale: en_US` обязательны: без них страница получит `<html lang="ru">`
  и `og:locale=ru_RU`.
- `permalink` строго `/en/articles/<slug>/` (со слешем в конце), `<slug>` — как у оригинала.
- `date` не менять и не ставить сегодняшнюю: это дата публикации статьи, а не перевода.
- `layout: default` и `nav_exclude: true` — как у оригинала, статьи не показываются в боковом меню.
- Первый заголовок `# …` в теле — перевод `title`.

## Картинки и ссылки

Картинки не копируй и не дублируй — ссылайся на файлы русской папки по абсолютному пути
сайта. В оригинале путь относительный (`assets/01.png`), но на URL `/en/articles/<slug>/`
он разрешился бы в несуществующее место и дал бы 404.

```markdown
![Alt text in English]({{ '/articles/<slug>/assets/01-name.png' | relative_url }})
```

- `alt` переводи.
- Если на скриншоте русский интерфейс, а он важен для понимания, сделай английскую
  подпись под картинкой («Screenshot of the Russian-language Telegram UI») или, если есть
  возможность, подготовь англоязычный вариант рядом: `assets/01-name.en.png`.
- Ссылки на другие статьи сайта: если у той статьи уже есть английская версия
  (`article.en.md`) — веди на `/en/articles/<other>/`, иначе на русский оригинал
  `/articles/<other>/`. Оборачивай в `{{ '…' | relative_url }}`.
- Внешние ссылки (GitHub и т.п.) оставляй как есть.

## Как переводить

Цель — статья, которая читается как написанная по-английски, а не как перевод.

- **Смысл и факты не меняй.** Числа, даты, время, названия сущностей, команды, цитаты
  диалогов, выводы — как в оригинале. Ничего не добавляй от себя и не «улучшай» аргументацию.
  Если в оригинале есть неточность — не исправляй молча, сообщи в отчёте.
- **Адаптируй, а не переводи дословно:** идиомы, шутки, разговорные обороты, порядок
  слов. Сохраняй голос автора: первое лицо, спокойная инженерная интонация, без рекламности.
- **Не трогай:** блоки кода, команды, имена файлов, идентификаторы, названия
  продуктов и проектов (`career-portal`, `gdebenz`, `Firebase`, `BigQuery`). В коде
  комментарии на русском переводи только если они важны для понимания и это не ломает пример.
- **Структура:** те же разделы, тот же порядок, те же заголовки уровня `##` (переведённые).
  Якоря Jekyll строит из заголовков сам, ручных якорей не задавай.
- **Имя автора:** Evgeny Khramov (в английском тексте и в подписях).
- **Термины:** держи единообразие по всему тексту (agent / coding agent / MCP server и т.д.);
  если не уверен в устоявшемся английском термине, оставь общепринятый английский и не выдумывай.
- **Качество важнее скорости.** Перевод должен быть полноценным: нельзя публиковать
  сокращённый пересказ, машинный подстрочник или заглушку. Тонкие страницы поисковики
  выбрасывают из индекса (так уже произошло со страницами `/projects/*` в Яндексе).
- Не переводи `articles/family-messenger-habr/` без отдельной просьбы.

## Карточка в английском индексе

Файл `en/articles/index.md`. Пока в нём только заглушка «coming soon». При добавлении
первого перевода замени заглушку на список и дальше добавляй по карточке на статью, в
том же формате, что в `articles/index.md`, но на английском:

```markdown
## <Translated title>

<2–3 предложения, перевод карточки из articles/index.md>

[Read the article]({{ '/en/articles/<slug>/' | relative_url }}){: .btn .btn-blue }
```

Фразу «English translations are coming soon» убери вместе с появлением первой карточки,
ссылку на русский раздел («Original articles in Russian») оставь.
Поля front matter `noindex` и `sitemap` не трогай.

Русский `articles/index.md` не меняй: ссылку «Read in English» в шапке статьи даёт
переключатель, остальное решает мета-агент.

## Порядок работы над одной статьёй

1. Прочитай русский оригинал целиком и папку `assets/`.
2. Проверь, что в оригинале нет неопубликованных правок (`git status` в репозитории).
3. Добавь `translation_key` в front matter оригинала.
4. Создай `article.en.md` по правилам выше.
5. Добавь карточку в `en/articles/index.md`.
6. Проверь:
   - YAML в обоих файлах валиден, `title`/`description` в кавычках;
   - `translation_key` одинаков, `permalink` соответствует шаблону;
   - все `{{ … | relative_url }}`-ссылки на картинки указывают на существующие файлы;
   - внутренних ссылок вида `assets/…` и `/hram/…` в английской версии нет;
   - код, числа, даты и имена совпадают с оригиналом;
   - нет остатков русского текста (кроме намеренных цитат и русских названий интерфейса).
7. Не коммить. Верни отчёт: какие файлы созданы или изменены, что было спорным в
   переводе, есть ли скриншоты с русским интерфейсом, замеченные неточности оригинала.

## Чего не делать

- Не создавай английские версии вне `articles/<slug>/article.en.md` и `en/articles/index.md`.
- Не меняй `_config.yml`, `_includes/`, `_layouts/`, `.github/`.
- Не добавляй `<link rel="alternate">`, переключатель языка или `canonical` в тело статьи:
  всё это генерируют шаблоны.
- Не ставь `canonical` английской версии на русскую: у каждой версии он свой.
- Не переводи и не правь русскую версию, кроме одной строки `translation_key`.
- Не отправляй URL в Яндекс.Вебмастер и GSC.
