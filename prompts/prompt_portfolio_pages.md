# Задача для Claude Code — страницы проектов + интеграция в сайт

## Контекст
Собираем публичное портфолио AI-построенных проектов на личном GitHub Pages сайте.
Есть два готовых эталона (сделаны заранее, менять их структуру нельзя — только копировать паттерн):

- **`project-galaxy.html`** — интерактивный хаб-«созвездие» (визуальный индекс всех проектов).
- **`meta-agent.html`** — эталонная страница одного проекта: статический краулабельный HTML со встроенным JSON-LD, в космическом визуальном языке. Внутри файла, в шапке, есть комментарий с полями-плейсхолдерами `[[…]]` и правилами.

Твоя работа — **размножить `meta-agent.html` на остальные 11 проектов** из брифов и **встроить всё в сайт**.

## Пути
- Сайт (Jekyll, тема Just the Docs): `/mnt/fastdata/hram/projects/hram`
- Брифы проектов: `/mnt/fastdata/hram/projects/spaces/ai-assisted/<папка>/PROJECT_BRIEF.md`
- Публичный адрес сайта: `https://hram.github.io/` (baseurl `/hram`)

## Шаг 0 — разместить эталоны
Файлы `project-galaxy.html` и `meta-agent.html` пользователь кладёт в корень репозитория сайта. Размести их так:
- `project-galaxy.html` → **в корень** сайта: `/mnt/fastdata/hram/projects/hram/project-galaxy.html`
- `meta-agent.html` → в подпапку: `/mnt/fastdata/hram/projects/hram/projects/meta-agent.html`

Создай папку `projects/` в корне сайта, если её нет.

## Как генерировать страницу
Для каждого проекта: прочитай его `PROJECT_BRIEF.md`, возьми `meta-agent.html` как шаблон, замени плейсхолдеры контентом из брифа:

- `[[CATEGORY]]` — текст eyebrow + `--accent` из таблицы. Установи `--accent:<hex>;` напрямую (не `var(--gold)`). Подгони и цвет фоновой заливки врезки `.relevance` под accent (низкая непрозрачность того же цвета).
- `[[TITLE]]` — имя проекта (заголовок `<h1>` и `<title>`).
- `[[ONE_LINER]]` — строка «Одной строкой» из брифа.
- `[[WHAT]]` — раздел «Что это» (2–4 предложения).
- `[[TASK]]` — «Задача, которую решает».
- `[[DEMONSTRATES]]` — из раздела «Что демонстрирует» брифа (3–4 пункта, `<b>лид</b>: пояснение`). Это ключевой блок ценности.
- `[[FACTS]]` — из таблицы «Факты» брифа: 4–6 сильнейших метрик (период, коммиты, объём кода, тесты, статус). Сетка на 3 колонки.
- `[[STACK]]` — «Стек и архитектура» кратко.
- `[[AI_TRACE]]` — «След AI-процесса» в 2–3 предложения (обобщённо).
- Врезка «Почему релевантно роли» — 1–2 честных предложения, связывающих проект с задачей «превратить удачные AI-кейсы в стандарт направления».
- `<meta name="description">`, `og:*`, `<link rel="canonical">` — обнови под проект. Canonical по шаблону `https://hram.github.io/projects/<file>.html`.
- `[[JSONLD]]` — обнови `name`, `abstract`/`headline`, `programmingLanguage`, `dateCreated`, `keywords`. Блок `author` (Person) оставь без изменений.

## Правила scrub (обязательно — витрина публичная)
Только **метод и метрики**. Убери всё внутреннее:
- **Нигде** не называть работодателя, внутренние хостнеймы, IP, имена корпоративных систем.
- `doctor`: только архитектура и концепция ИИ-извлечения. **Без** медицинских данных, без скриншотов, без названий клиник.
- `impact-analysis`: **не** называть реальный проект/приложение, на котором проверялось. Писать «реальный Android-проект (крупная кодовая база)». Метрики вида «91 экран» — можно.
- `gitlab-panel`: GitLab/Jira — обобщённые инструменты, ок; внутренние процессы/названия не раскрывать.
- Ссылку на репозиторий (`.foot .primary`) добавлять **только** если проект реально публичный. По умолчанию — не добавлять (репозитории приватные). Для `family-messenger`: если есть опубликованная статья на Habr — можно поставить её публичной ссылкой в футер; если нет — не ставить.

## Требования к каждой странице
- **Без YAML front matter** — файлы должны отдаваться Jekyll как статические (passthrough), а не заворачиваться в тему Just the Docs. Проверь, что в собранном `_site` страница не содержит сайдбар/навигацию JtD.
- Весь контент — в статическом HTML (JS только рисует фон). Никакого контента, подгружаемого скриптом, — важна краулабельность.
- Сохрани из шаблона: адаптив, видимый focus, `prefers-reduced-motion`, JSON-LD.
- Внутренние ссылки: назад — `../project-galaxy.html`; из галактики — уже `projects/<id>.html`. Проверь, что все резолвятся, мёртвых ссылок нет.

## Интеграция в сайт
1. На главной странице сайта (`index.md` / домашняя страница) добавь заметную ссылку-карточку на созвездие: заголовок вроде «Созвездие AI-проектов →», ведёт на галактику. Внутри Jekyll-страниц используй фильтр `relative_url` (учитывает baseurl `/hram`), например `{{ '/project-galaxy.html' | relative_url }}`. В статических HTML — обычные относительные пути (не трогай, они уже верные).
2. Существующий контент сайта (резюме, career-focus, impact, Tech Radar) не ломать.

## Шаг (опционально, если несложно) — фикс canonical
В `_config.yml` проверь `url`/`baseurl`. Если canonical на страницах двоится (`.../hram//hram/`), выстави:
```yaml
url: "https://hram.github.io"
baseurl: "/hram"
```
