# Структура статьи для vc.ru

## Рабочая идея

Небольшая техническая история не столько о CameraX, сколько о том, как
выглядит реальная отладка с coding agent: агент имеет доступ к коду,
`adb`, логам и MR, делает почти всю механическую работу, но разработчик
остаётся ответственным за постановку эксперимента, оценку гипотез и
остановку плохих решений.

## Варианты заголовка

Основной:

**Coding agent почти починил мне CameraX задержкой. Почему я его
остановил**

Более нейтральный:

**Как я отлаживал CameraX с coding agent: баг, физический планшет и одна
плохая гипотеза**

Технический:

**Preview правильный, ImageAnalysis вверх ногами: как мы с coding agent
искали причину бага CameraX**

## 1. Hook: одна камера --- две ориентации

Коротко описать баг.

``` text
Camera
├── Preview       → всё нормально
└── ImageAnalysis → кадр перевёрнут на 180°
```

Планшет переворачивается на 180°. Пользовательское preview остаётся
правильным, анализ получает неправильную ориентацию.

Сразу добавить необычную часть истории: почти всю работу с проектом,
логами и кодом выполнял coding agent; автор взаимодействовал с
физическим планшетом и управлял расследованием.

### Артефакты

-   простая схема двух потоков CameraX;
-   при наличии --- кадр/скриншот, показывающий проблему;
-   короткий фрагмент исходного лога.

------------------------------------------------------------------------

## 2. Как выглядела работа с агентом

Не объяснять AI вообще. Показать реальный рабочий цикл.

``` text
Я: «запускай запись, я переверну экран»
Агент: запускает adb/logcat
Я: физически переворачиваю планшет
Агент: читает результаты
Агент: меняет instrumentation/code
Повторяем эксперимент
```

Подчеркнуть: это не копирование stack trace в чат. Агент работает
непосредственно с проектом и инструментами.

### Артефакты

-   короткий реальный фрагмент диалога;
-   при желании --- скрин терминала с `adb logcat`;
-   схема «человек ↔ агент ↔ проект/устройство».

------------------------------------------------------------------------

## 3. Первая гипотеза и red flag

Показать, что агент обнаружил задержку обновления `display.rotation`.

Смысл его первоначального решения:

``` text
DisplayListener
→ значение ещё старое
→ подождать
→ получить новое значение
→ rebind
```

Автор останавливает это направление.

Важная мысль: в этот момент автор ещё не обязан знать правильное
решение. Достаточно увидеть, что корректность начинает зависеть от
тайминга.

Фраза-смысл раздела:

> Я не знал ещё, чем именно это надо заменить. Но уже знал, что
> «подождём полсекунды и перебиндим камеру» --- плохой фундамент для
> исправления.

### Артефакты

-   цитата агента: «через \~0,5 с реальное значение становится
    displayRotation=3»;
-   небольшой псевдо-diff или схема старого подхода;
-   не показывать большой листинг.

------------------------------------------------------------------------

## 4. Вместо patch --- эксперимент

Переход от запроса «исправь» к запросу «докажи, почему происходит».

Показать, какие значения начали измерять:

``` text
Configuration.orientation
displayRotation
Preview.targetRotation
ImageAnalysis.targetRotation
ImageProxy.rotationDegrees
```

Объяснить, что задача стала диагностической: найти первое место, где
состояние расходится.

### Артефакты

-   компактный блок с набором диагностических полей;
-   при желании --- маленький diff добавленного logging.

------------------------------------------------------------------------

## 5. Логи, которые всё объяснили

Показать пару «до/после».

До:

``` text
Configuration.orientation=2
displayRotation=1
analysisTargetRotation=1
imageRotation=0
```

После:

``` text
Configuration.orientation=2
displayRotation=3
analysisTargetRotation=1
imageRotation=0
```

Затем буквально в нескольких абзацах объяснить:

``` text
ROTATION_90  → ROTATION_270
landscape    → landscape
```

`Configuration.orientation` не изменился, реальный display rotation
изменился, а `ImageAnalysis.targetRotation` остался прежним.

Root cause теперь не гипотеза, а наблюдаемая цепочка.

### Артефакты

-   главный лог «до/после»;
-   схема рассинхронизации:

``` text
device/display       270°
ImageAnalysis target  90°  ← проблема
```

Это центральный технический артефакт статьи.

------------------------------------------------------------------------

## 6. Исправление оказалось проще workaround

Показать концептуальный diff:

``` text
- DisplayListener
- post / ожидание
- rebind

+ OrientationEventListener
+ preview.targetRotation = rotation
+ imageAnalysis.targetRotation = rotation
```

Не уходить глубоко в документацию CameraX.

Упомянуть важную деталь: соответствие градусов
`OrientationEventListener` и `Surface.ROTATION_*` оказалось неочевидным,
и диапазон 45..134° должен был давать `ROTATION_270`.

### Артефакты

-   короткий реальный diff;
-   5--10 строк кода итогового обработчика, если они читаемы;
-   ссылка на MR/репозиторий только если код можно публиковать.

------------------------------------------------------------------------

## 7. Проверка: не «кажется, работает», а измеримый результат

До:

``` text
displayRotation=1
analysisTargetRotation=1
imageRotation=0
```

После физического переворота:

``` text
orientationDegrees=70..79
calculatedRotation=3
displayRotation=3
analysisTargetRotation=3
imageRotation=180
```

Отдельно сказать:

-   Preview не пересоздавался;
-   ImageAnalysis не пересоздавался;
-   rebind не выполнялся;
-   задержек нет.

### Артефакты

-   финальный лог;
-   при наличии --- короткое видео/GIF с переворотом и успешным
    сканированием.

  Обновлял MR             Определял, что считать корректным

Не преуменьшать вклад агента и не изображать его магией.

## 9. Вывод

Не делать общих заявлений вроде «AI заменит программистов».

Вывод конкретнее:

> В этой задаче я почти не занимался механическим редактированием кода и
> сбором диагностических данных. Но именно инженерная оценка
> предложенного агентом решения изменила направление расследования.

Второй вывод:

> Coding agent полезен не тогда, когда безоговорочно выполняет «почини
> баг», а когда с ним можно быстро прогонять проверяемые инженерные
> гипотезы.

Финальная мысль:

> Я всё меньше работаю как человек, который сам выполняет каждый шаг, и
> всё больше --- как человек, который задаёт эксперимент, проверяет
> доказательства и управляет исполнителем.

На этом закончить. Не рекламировать следующую статью и не растягивать
вывод.
