# Как я перестал проверять каждый черновик ролика в Remotion

![В исходном Remotion MCP цикл правок проходит между человеком и агентом. В форке он замкнут на агенте, который передаёт человеку готовый MP4.]({{ '/articles/remotion-mcp-app/assets/cover.png' | relative_url }})

Я прошу агента сделать ролик. Он присылает черновик. Я смотрю, нахожу замечание и отправляю его обратно. Агент исправляет, и я снова смотрю. Так может пройти несколько кругов.

С моим [форком Remotion MCP App](https://github.com/hram/remotion-mcp-app) я даю задачу и впервые смотрю ролик, когда агент уже его проверил. По дороге он сам получает кадры, замечает ошибки, правит композицию и проверяет её снова. Я могу даже не узнать, что было в промежуточных версиях.

## Кто проходит цикл правок

**Исходный Remotion MCP App:** агент делает черновик → я смотрю и отправляю замечания → агент правит → я снова смотрю.

**Мой форк:** я даю задачу → агент делает черновик → **смотрит, правит и снова смотрит** → я получаю проверенный MP4.

В первом случае следующий круг начинается, когда я посмотрю правку и отвечу. Во втором агент сам решает, нужен ли ещё один круг по моим критериям. В [коротком ролике]({{ '/articles/remotion-mcp-app/assets/video/remotion-frame-review-x-ru.mp4' | relative_url }}) видно, как путь черновиков и замечаний замыкается внутри агента.

## Как агент проверяет свою работу

`inspect_frames` возвращает агенту лист с пронумерованными кадрами текущей версии прямо в ответе MCP. На нём видно, например, что первый кадр пустой или заголовок обрезан. Агент исправляет композицию и смотрит те же кадры ещё раз. Если проблема осталась или появилась новая, он повторяет проверку после следующей правки.

Для ролика 1920×1080 агенту можно дать семь кадров по 480×270. Remotion сразу рендерит их в этом размере. Полноразмерное видео появляется в конце, когда агент вызывает `export_video` и получает ссылку на MP4.

Мне остаётся посмотреть готовый файл и принять решение о публикации. По выборке кадров удобно проверять компоновку и видимые состояния. Темп и плавность я оцениваю при воспроизведении.

## Как попробовать

Для локального запуска нужен Node.js 22.22.2 или новее. При первом рендере Remotion может скачать Chrome Headless Shell. [Требования и запуск](https://github.com/hram/remotion-mcp-app/blob/main/README.ru.md#локальный-запуск)

```bash
git clone https://github.com/hram/remotion-mcp-app.git
cd remotion-mcp-app
npm ci
npm run dev -- --host 127.0.0.1 --port 3000
```

Подключите MCP-клиент к `http://localhost:3000/mcp` по Streamable HTTP. Выберите модель, которая может анализировать изображения из ответов MCP.

Вот запрос, с которого можно начать:

> Сделай семисекундный ролик 1920×1080, 30 кадров/с, без звука. Покажи, как пользователь выбирает маршрут на карте. На первом кадре уже должны быть видны карта и заголовок. Подписи должны читаться и целиком помещаться в кадр. Через `inspect_frames` посмотри семь кадров, включая первый, последний и моменты смены сцены. Если заметишь проблему, исправь её и снова проверь затронутые кадры. Продолжай этот цикл сам. Когда кадры будут соответствовать критериям, один раз вызови `export_video` с `muted: true` и пришли ссылку на MP4.

Скачайте файл, пока сервер работает. Если вызываете инструменты из скрипта, используйте один идентификатор сессии для создания, проверок, правок и экспорта. Сервер принимает `_meta["openai/session"]` или заголовок `x-remotion-session-id`. [Пример вызовов MCP](https://github.com/hram/remotion-mcp-app/blob/main/examples/android-ui-renderer-x/pipeline.ts)
